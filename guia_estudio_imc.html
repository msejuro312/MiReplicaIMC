Guía de Estudio · MiniProyecto: Calculadora de IMC

Repaso paso a paso para el curso Desarrollo de Aplicaciones Móviles.

Proyecto: MiReplicaIMC · Paquete com.example.mireplicaimc · 100% Kotlin

Android Kotlin ViewBinding Material 3

1. Introducción

Este mini proyecto construye una calculadora de Índice de Masa Corporal (IMC) con dos pantallas:

  • Pantalla 1 (formulario): el usuario ingresa su nombre, peso (kg) y estatura (m).
  • Pantalla 2 (resultado): muestra el nombre, el IMC calculado y su clasificación (bajo peso, normal, sobrepeso u obesidad).

Al finalizar aprenderás a:

  • Crear un proyecto Android con Empty Views Activity en Kotlin.
  • Entender qué hace el sistema de compilación Gradle y sus archivos de configuración.
  • Leer y modificar el AndroidManifest.xml.
  • Crear interfaces con XML usando Material Components (TextInputLayout, MaterialButton).
  • Conectar la interfaz con la lógica mediante ViewBinding.
  • Navegar entre pantallas con Intent y pasar datos mediante extras.
  • Implementar validación de formularios mostrando errores en cada campo.
  • Aplicar la fórmula y clasificación del IMC según la OMS.

2. Crear el proyecto paso a paso

2.1 Nuevo proyecto

  1. Abre Android Studio y ve a File → New → New Project.
  2. Elige la plantilla Empty Views Activity (usa XML, no Compose).
  3. Configura así el asistente:
    CampoValor¿Por qué?
    NameMiReplicaIMCNombre visible del proyecto.
    Package namecom.example.mireplicaimcIdentificador único (como un DNI de la app). Define la carpeta del código.
    LanguageKotlinLenguaje nativo moderno de Android.
    Minimum SDKAPI 26 (Android 8.0)La versión mínima del celular donde correrá la app (~97% de dispositivos).
    Build configuration languageKotlin DSL (build.gradle.kts)Los archivos de build se escriben en Kotlin (más moderno que Groovy).
  4. Presiona Finish y espera la sincronización de Gradle (Android Studio descarga las dependencias; la barra de progreso aparece abajo).
Concepto clave El package name (o applicationId) identifica tu app de forma única. Debe ser distinto si ya instalaste la app del profesor en el emulador, para que no se sobren los datos.

4. Gradle: ¿qué hace cada archivo?

Gradle es el sistema de automatización que descarga librerías y compila tu app. Entenderlo te salva de muchos "errores de sincronización".

4.2 Tu código: el bloque buildFeatures LO COMPLETAS TÚ

Este es el fragmento exacto que debes escribir a mano dentro del bloque android { ... }:

buildFeatures {
    viewBinding = true
}
Línea¿Qué hace?
buildFeatures {Abre el conjunto de funciones de compilación opcionales. Aquí se activan ViewBinding, Compose, etc.
viewBinding = trueActiva ViewBinding: por cada archivo de layout, Gradle genera una clase (p. ej. activity_main.xml → ActivityMainBinding) que nos da acceso directo a los elementos por su android:id, sin usar findViewById.
No olvides sincronizar Después de escribir este bloque debes pulsar Sync Now (o File → Sync Project with Gradle Files). Solo así Gradle genera las clases de binding y Android Studio deja de marcar en rojo ActivityMainBinding.

5. AndroidManifest.xml

Declara las dos Actividades y qué hace cada una en el sistema:

<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:supportsRtl="true"
        android:theme="@style/Theme.MiReplicaIMC">

        <activity
            android:name=".ResultadoActivity"
            android:exported="false" />

        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
    </application>
</manifest>
Elemento / atributo¿Para qué sirve?
<application>Nodo raíz de la app: aquí se agrupan todos los componentes.
android:label="@string/app_name"Nombre que se muestra bajo el ícono en el launcher. Referencia a strings.xml.
android:theme="@style/Theme.MiReplicaIMC"Tema global definido en themes.xml (colores de la barra de estado, etc.).
<activity android:name=".MainActivity" android:exported="true">.MainActivity = clase dentro del paquete. exported=true + intent-filter MAIN/LAUNCHER indica que es la pantalla de inicio (la que arranca al abrir la app).
<activity android:name=".ResultadoActivity" android:exported="false">Segunda pantalla. exported=false porque solo puede abrirla la propia app (no otros programas).
Regla de oro Cada Activity que exista en tu código DEBE estar declarada aquí. Si agregas ResultadoActivity en Kotlin pero no la declaras, la app crashea al intentar abrirla.

Elemento¿Para qué funciona?
ScrollViewContenedor que permite desplazamiento vertical cuando el contenido excede la pantalla (teclado abierto, pantallas pequeñas). fillViewport="true" hace que el fondo llene la altura aunque haya poco contenido. Solo admite UN hijo directo.
LinearLayout externoDispone los hijos en una sola columna (orientation="vertical") con padding uniforme screen_padding.

LinearLayout con bg_surface_panelTarjeta blanca con borde que agrupa el formulario.
TextView "Datos personales"Encabezado de sección en azul oscuro.
TextView "El cálculo utiliza..."Nota explicativa de la fórmula, en gris.
TextInputLayout (inputLayoutNombre)Contenedor de Material que envuelve un campo de texto y sabe mostrar mensajes de error debajo del campo (lo usamos con binding.inputLayoutNombre.error). El estilo OutlinedBox dibuja el borde.
TextInputEditText (editTextNombre)El campo donde se escribe. inputType="textCapWords" activa el teclado de texto con mayúscula inicial.
TextInputLayout/EditText pesoinputType="numberDecimal" abre el teclado numérico con decimal. app:suffixText="@string/unidad_kilogramos" agrega el sufijo "kg". importantForAutofill="no" desactiva el autocompletado en un campo numérico.
TextInputLayout/EditText estaturaIgual que el peso, con sufijo "m".
MaterialButton (buttonCalcular)Botón Material en ancho completo (match_parent) y alto button_height. textAllCaps="false" evita el texto en MAYÚSCULAS automático.
Clave para ViewBinding Los android:id definidos aquí generan automáticamente referencias en las clases de binding: inputLayoutNombre → binding.inputLayoutNombre, buttonCalcular → binding.buttonCalcular, etc. Por eso los IDs deben coincidir exactamente con los que uses en Kotlin.

9. Arquitectura y flujo

Este proyecto usa un patrón sencillo y clásico de Android: dos Actividades que se comunican mediante un Intent.

9.1 ¿Qué es una Activity?

Una Activity es una pantalla de la app. Tiene un ciclo de vida y su método principal es onCreate(), que se ejecuta UNA vez cuando se crea:

  1. onCreate → se crea la pantalla (inflamos el layout y configuramos botones).
  2. onStart / onResume → la pantalla se muestra y queda interactiva.
  3. onPause / onStop → otra pantalla la cubre (por ejemplo, al navegar).
  4. onDestroy → la pantalla se destruye.

9.2 ¿Qué es ViewBinding?

Es el mecanismo que activaste con buildFeatures { viewBinding = true }. Por cada layout genera una clase que expone sus vistas. Ejemplo:

private lateinit var binding: ActivityMainBinding

binding = ActivityMainBinding.inflate(layoutInflater) // convierte el XML en vistas
setContentView(binding.root)                          // las muestra en pantalla
binding.buttonCalcular.setOnClickListener { ... }      // sin findViewById

Beneficios: código más corto, menos errores (si un ID no existe falla en compilación, no en ejecución) y tipado seguro.

9.3 ¿Qué es un Intent con extras?

Un Intent es un "mensaje para navegar". Puede llevar datos adicionales (extras) en un Bundle:

val intent = Intent(this, ResultadoActivity::class.java).apply {
    putExtra(ResultadoActivity.EXTRA_NOMBRE, nombre)
    putExtra(ResultadoActivity.EXTRA_IMC, imc)
    putExtra(ResultadoActivity.EXTRA_CLASIFICACION, clasificacion)
}
startActivity(intent)

La pantalla destino los recupera con intent.getStringExtra(...) o intent.getDoubleExtra(...).

9.4 Diagrama del flujo completo

  1. El usuario abre la app → Android lanza MainActivity (por el intent-filter del manífest).
  2. onCreate infla activity_main.xml y asocia el clic del botón.
  3. El usuario escribe nombre, peso y estatura y presiona Calcular IMC.
  4. Se valida cada campo; si algo falla, se muestra el error bajo el campo y se detiene.
  5. Si todo es válido → calcularIMC() y clasificarIMC().
  6. Se crea un Intent con los 3 extras y se llama startActivity().
  7. Se abre ResultadoActivity → onCreate infla activity_resultado.xml y llama mostrarResultado().
  8. mostrarResultado() lee los extras y pinta los 3 TextView.
  9. Si el usuario presiona Realizar otro cálculo → finish() cierra la pantalla y vuelve al formulario.

10. Tu código: MainActivity.kt LO COMPLETAS TÚ

Responsabilidad: mostrar el formulario, validar los datos, calcular el IMC y enviar los resultados a la otra pantalla.

package com.example.mireplicaimc

import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity
import android.content.Intent
import com.example.mireplicaimc.databinding.ActivityMainBinding

class MainActivity : AppCompatActivity() {
    private lateinit var binding: ActivityMainBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        binding = ActivityMainBinding.inflate(layoutInflater)
        setContentView(binding.root)

        binding.buttonCalcular.setOnClickListener {
            calcularYMostrarResultado()
        }
    }

    private fun calcularYMostrarResultado() {
        val nombre = binding.editTextNombre.text.toString().trim()
        val peso = binding.editTextPeso.text.toString().toDoubleOrNull()
        val estatura = binding.editTextEstatura.text.toString().toDoubleOrNull()
        var formularioValido = true

        binding.inputLayoutNombre.error = null
        binding.inputLayoutPeso.error = null
        binding.inputLayoutEstatura.error = null

        if (nombre.isBlank()) {
            binding.inputLayoutNombre.error = getString(R.string.error_nombre)
            formularioValido = false
        }
        if (peso == null || peso <= PESO_MINIMO) {
            binding.inputLayoutPeso.error = getString(R.string.error_peso)
            formularioValido = false
        }
        if (estatura == null || estatura <= ESTATURA_MINIMA) {
            binding.inputLayoutEstatura.error = getString(R.string.error_estatura)
            formularioValido = false
        }
        if (!formularioValido || peso == null || estatura == null) {
            return
        }

        val imc = calcularIMC(peso, estatura)
        val clasificacion = clasificarIMC(imc)

        val intent = Intent(this, ResultadoActivity::class.java).apply {
            putExtra(ResultadoActivity.EXTRA_NOMBRE, nombre)
            putExtra(ResultadoActivity.EXTRA_IMC, imc)
            putExtra(ResultadoActivity.EXTRA_CLASIFICACION, clasificacion)
        }
        startActivity(intent)
    }

    private fun calcularIMC(peso: Double, estatura: Double): Double {
        return peso / (estatura * estatura)
    }

    private fun clasificarIMC(imc: Double): String {
        return when {
            imc < LIMITE_PESO_NORMAL -> getString(R.string.clasificacion_bajo_peso)
            imc < LIMITE_SOBREPESO -> getString(R.string.clasificacion_peso_normal)
            imc < LIMITE_OBESIDAD -> getString(R.string.clasificacion_sobrepeso)
            else -> getString(R.string.clasificacion_obesidad)
        }
    }

    companion object {
        private const val PESO_MINIMO = 0.0
        private const val ESTATURA_MINIMA = 0.0
        private const val LIMITE_PESO_NORMAL = 18.5
        private const val LIMITE_SOBREPESO = 25.0
        private const val LIMITE_OBESIDAD = 30.0
    }
}

11. Tu código: ResultadoActivity.kt LO COMPLETAS TÚ

Responsabilidad: recibir los datos del Intent y mostrarlos.

package com.example.mireplicaimc

import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity
import com.example.mireplicaimc.databinding.ActivityResultadoBinding

class ResultadoActivity : AppCompatActivity() {
    private lateinit var binding: ActivityResultadoBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        binding = ActivityResultadoBinding.inflate(layoutInflater)
        setContentView(binding.root)

        mostrarResultado()

        binding.buttonVolver.setOnClickListener {
            finish()
        }
    }

    private fun mostrarResultado() {
        val nombre = intent.getStringExtra(EXTRA_NOMBRE)
            ?: getString(R.string.valor_no_disponible)
        val imc = intent.getDoubleExtra(EXTRA_IMC, IMC_POR_DEFECTO)
        val clasificacion = intent.getStringExtra(EXTRA_CLASIFICACION)
            ?: getString(R.string.valor_no_disponible)

        binding.textViewNombreResultado.text =
            getString(R.string.resultado_nombre_formato, nombre)
        binding.textViewImcResultado.text =
            getString(R.string.resultado_imc_formato, imc)
        binding.textViewClasificacionResultado.text = clasificacion
    }

    companion object {
        const val EXTRA_NOMBRE = "extra_nombre"
        const val EXTRA_IMC = "extra_imc"
        const val EXTRA_CLASIFICACION = "extra_clasificacion"
        private const val IMC_POR_DEFECTO = 0.0
    }
}

12. Lógica del IMC

12.1 La fórmula

El Índice de Masa Corporal relaciona el peso con la estatura:

SímboloSignificadoEn nuestro código
PesoKilogramos (kg)peso
EstaturaMetros (m)estatura
IMCpeso / estatura²peso / (estatura * estatura)

Ejemplo: un peso de 70 kg y 1.75 m → 70 / (1.75*1.75) = 22.86.

12.2 Clasificación según la OMS

CategoríaRangoCondición en el when
Bajo pesomenos de 18.5imc < 18.5
Peso normal18.5 a 24.9imc < 25 (después de descartar <18.5)
Sobrepeso25.0 a 29.9imc < 30
Obesidad30 o máselse

12.3 Por qué se usan < (no <=)

El when evalúa de arriba hacia abajo y se detiene en la primera condición verdadera. Con <:

  • IMC = 18.5 → pasa la 1ª (<18.5 es falso) → cae en "Peso normal". Correcto según OMS, porque 18.5 YA es normal.
  • IMC = 25.0 → cae en "Sobrepeso". Correcto.
  • IMC = 30.0 → cae en "Obesidad". Correcto.
Orden importa Las condiciones van de menor a mayor. Si las cambias de orden, los rangos se desordenarían. Es un clásico en toda sustentación.

13. Errores comunes (los que corregiste)

13.1 "OnCreate overrides nothing"

Causa Escribiste OnCreate con mayúscula. Kotlin distingue mayúsculas/minúsculas: el método real de AppCompatActivity es onCreate (a minúsculas). Con OnCreate le dices a Kotlin "inventa un método nuevo que no existe". 
// ❌ Mal
override fun OnCreate(savedInstanceState: Bundle?) {

// ✅ Bien
override fun onCreate(savedInstanceState: Bundle?) {

13.2 Falta .text al leer el campo de estatura

Causa binding.editTextEstatura.toString() devuelve la representación del objeto, no lo que escribió el usuario. Por eso la estatura siempre daba null y nunca validaba. 
// ❌ Mal (lee el objeto del campo)
val estatura = binding.editTextEstatura.toString().toDoubleOrNull()

// ✅ Bien (lee el TEXTO del campo)
val estatura = binding.editTextEstatura.text.toString().toDoubleOrNull()

13.3 Faltó el argumento del formato %1$.2f

Causa La string "IMC: %1$.2f" espera un valor. Sin el argumento, en ejecución se lanza MissingFormatArgumentException (la app se cierra). El formato exige pasarle el dato que reemplaza al "hueco". 
// ❌ Mal (falta el valor)
getString(R.string.resultado_imc_formato)

// ✅ Bien (se le pasa imc)
getString(R.string.resultado_imc_formato, imc)

13.4 ScrollView con wrap_content en lugar de match_parent

Causa Si la raíz ScrollView mide wrap_content, no ocupa la pantalla completa y el fondo degradado puede quedar cortado. La raíz de la pantalla debe ser match_parent. 
// ✅ Bien
android:layout_width="match_parent"
android:layout_height="match_parent"

14. Buenas prácticas aplicadas

  • Textos externalizados: ningún texto "quemado" en el código o layout; todo en strings.xml. Facilita traducciones y evita fugas de texto.
  • Colores y medidas en recursos: paleta y tamaños centralizados; cambiar el tema se hace en un solo lugar.
  • Constantes con significado: los límites del IMC en const val dentro del companion object; se leen mejor que un 18.5 suelto y se reutilizan.
  • Validación amigable: los errores aparecen exactamente bajo el campo que falla usando el mecanismo de TextInputLayout.
  • Defensa ante datos faltantes: en ResultadoActivity se usan valores por defecto (?: y IMC_POR_DEFECTO) para no crashear nunca.
  • Nombres de IDs descriptivos: prefijo que indica el tipo (inputLayout_, editText_, textView_, button_) y la función, en camelCase.
  • Separar lógica de la interfaz: cálculo y clasificación están en métodos privados, fáciles de entender y probar.
  • Mensaje de responsabilidad: la nota final recuerda que el IMC es una referencia, no un diagnóstico.
